Цепочка обязанностей

Запрос проходит через последовательность обработчиков — пока один из них не возьмёт его на себя.

Пример реализации на Java

01 / Проблема

Когда один метод
знает слишком много

Представим обработку заказа в интернет-магазине.

Без паттерна

Один большой обработчик

  • Проверяет авторизацию
  • Проверяет наличие товара
  • Проверяет оплату
  • Подтверждает заказ

Клиентский код разрастается и зависит от всех проверок.

С паттерном

Отдельные обработчики

Авторизация
↓
Проверка товара
↓
Проверка оплаты

Каждый объект отвечает за свою часть и может передать запрос дальше.

02 / Устройство

Запрос движется
по цепочке

Отправитель знает только первый обработчик. Остальное решает сама цепочка.

Client
отправляет запрос
Handler Aпроверка
→
Handler Bпроверка
→
Handler Cпроверка
  • Handler — общий контракт обработчика.
  • ConcreteHandler — конкретная проверка и обработка.
  • next — ссылка на следующего участника цепочки.

Обработчик либо принимает запрос, либо передаёт его дальше. Если цепочка закончилась, запрос может остаться необработанным.

04 / Оценка паттерна

Плюсы и ограничения

Преимущества
  • Слабая связанность: отправителю не нужно знать конкретного обработчика.
  • Расширяемость: новый обработчик можно добавить без изменения клиента.
  • Гибкость: порядок и состав цепочки можно менять.
  • Единая ответственность: каждый обработчик решает одну задачу.
Недостатки
  • Нет гарантии обработки: запрос может дойти до конца цепочки без результата.
  • Сложнее отладка: не всегда очевидно, какой обработчик получит запрос.
  • Затраты на проход: длинная цепочка добавляет проверки и переходы.
  • Порядок важен: неверная последовательность может привести к неправильной обработке.

Паттерн полезен, когда заранее неизвестно, кто именно должен обработать запрос, а набор обработчиков может меняться.

05 / Реализация на Java

В коде это
выглядит просто

public abstract class SupportHandler {
    private SupportHandler next;

    public SupportHandler setNext(
            SupportHandler next) {
        this.next = next;
        return next;
    }

    public void handle(SupportRequest r) {
        if (canHandle(r)) {
            process(r);
        } else if (next != null) {
            next.handle(r);
        }
    }

    protected abstract boolean
        canHandle(SupportRequest r);
    protected abstract void
        process(SupportRequest r);
}

① setNext()

Связывает обработчики в цепочку.

② canHandle()

Определяет, подходит ли текущий обработчик.

③ process() / next.handle()

Обрабатывает запрос или передаёт его дальше.
